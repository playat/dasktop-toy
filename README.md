# 桌宠工作区

> **本项目是基于开源项目 [PC2005-cloud/dsh-pet](https://github.com/PC2005-cloud/dsh-pet) 重构的桌面独立版。**
> 上游是「DSH 插件 + Electron 桌面 Helper」的形态；这里用 PySide6 + PyAV 重写成**不依赖
> Node / Electron / DSH 也能跑**的纯 Python 桌面程序，并尽量把上游的功能补回来（对照表见第 6 节）。

两件事：**把 AI 生成的绿幕视频加工成透明 webm**，以及**把这些 webm 当成桌宠跑起来**。

```
dsh-pet/
├── .venv/                      工作区统一虚拟环境（运行 + 素材工具共用）
├── requirements.txt
├── run-pet.cmd                 启动桌宠（源码模式；启动前先自检 .venv 与依赖）
│
├── main.py                     运行时入口
├── window.py player.py video.py config.py physics.py menu.py tray.py
├── bubble.py                   说话气泡（原 client/bubble.ts 的 PySide 版）
├── saybox.py                   宠物右侧的对话输入框（同一套白底圆角观感）
├── basket.py                   投篮小游戏：可拖的篮筐 + 头顶计分 + 判定
├── events.py                   事件编排：说话/表情包/余额/工作状态/通知
├── dsh.py                      DSH 对接（轮询 /dsh-pet-7340 契约，可选）
├── session.py                  会话日志观察：读日志折叠状态 + 触发决策（可当命令行用）
├── balance.py                  余额直连：读 dsh 凭据问 DeepSeek Platform（可当命令行用）
├── ai.py                       本机大模型（OpenAI 兼容，可选）
├── memes.py                    表情包池
├── config.jsonc                配置（JSONC，带注释）
├── basket-score.json           投篮最高分（运行时生成，不进 git）
│
├── make_pet_webm.py            素材生成工具（一条命令，单遍管线，默认增量）
├── build.py                    打包成 exe（python build.py）
├── prompts/                    AI 生成提示词配方（106 个动作 + 通知图标两套）
├── video/
│   ├── watermark_mask_v5.mkv   水印遮罩（1280×720）
│   └── src/                    ← 原始绿幕视频放这里（mp4 / mov / webm / mkv）
│
├── assets/                     ← 项目文件：素材的「源」，进 git，源码模式直接读
│   ├── webm/                  动画（按目录名决定用途，见下文）
│   ├── memes/                 表情包（27 张 png，文件名 = 配置里的键）
│   ├── pic/                   通知图标 + 拖拽光标
│   ├── sound/click-duck.wav   点击音效
│   └── fonts/上首软糖体.ttf    气泡字体
│
└── dist/                       构建产物：一条 build 就能整个重建，可整包搬走
    ├── DshPet.exe              跑一次 python build.py 就有
    ├── _internal/              Qt / PyAV / numpy 等运行时
    ├── config.jsonc            打包时从根目录复制一份
    └── assets/                按 assets/ 镜像出来的一份（多出来的会删掉）
```

数据流是一条直线：

```
prompts/  →  AI 生成  →  video/src/*.mp4  →  make_pet_webm.py  →  assets/webm/*.webm
                                                                         │
                                          ┌──────────────────────────────┴────────────┐
                                          ▼                                           ▼
                              run-pet.cmd（读工程 assets/）      python build.py ──► dist/（整包可搬）
```

两个目录分工明确：

- **`assets/` 是项目文件**（进 git）—— 素材的源。生成工具写这里，源码模式运行时读这里。
- **`dist/` 是构建产物**（不进 git）—— `build.py` 打包前把 `assets/` 整个镜像一遍，
  里面每一样东西都能从工程文件重建出来。拷给别人就能跑，自己删了也不心疼。

改了代码或换了素材，跑一次 `python build.py`，`dist/` 就变成与工程内容一致的、可直接分发的一版。

数据来源只在运行时决定：**能读会话日志就用它（工作状态），有 DSH 再接 DSH，没有就用本机模型，
都没有就纯本地**（第 2 节）。

## 1. 跑起来

首次准备环境（只做一次，在本目录执行）：

```bat
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

之后启动。`run-pet.cmd` 会先自检 —— 没有 `.venv`、venv 里的 python 起不来、
依赖缺了哪个，都直接说清楚该怎么办，不会甩一堆 traceback：

```bat
run-pet.cmd
```

也可以不经过 .cmd，直接用自己的解释器跑：

```bat
.venv\Scripts\python.exe main.py
```

手动激活环境（想跑别的脚本时）：

```bash
source .venv/Scripts/activate      # Git Bash
.venv\Scripts\activate.bat         # cmd
.venv\Scripts\Activate.ps1         # PowerShell
```

- 右键宠物：顶部「动作」点播（第一项是表情包子菜单）、大小、固定原地、投篮游戏、回到初始位置、重载配置，
  然后平铺的 **碎碎念 / 说句话… / 刷新余额 / 再来一只**，最后一项只剩一只时是「退出」，
  开了多只时变成「关掉这只」—— 只收掉右键的那一只，最后一只关掉才退出程序
- 「说句话…」**不弹对话框**：直接在宠物**右侧**开一条输入框（右边放不下就翻到左边，尾巴跟着换边），
  回车发送、Esc 收起，宠物走动/被拖时输入框跟着走（见 2.11）
- 自己动的时候，两次动作之间会歇一段随机时间（平时 2~5.5s，动作后更久，偶尔发呆；
  机器忙时更安静），这段时间插一段待机动画，不会一个接一个赶场 —— 参数见 `animGap`
- 拖拽：松手站住；**甩出去**才会飞、撞墙反弹、落地压一下
- 托盘图标：显示/隐藏、再来一只、全部回到初始位置、重载配置、退出
- 终端里 `Ctrl+C` 退出

配置在 `config.jsonc`（JSONC，带注释），改完右键「重载配置」即可，不用重启。
顶层就这些键：`pets` `physics` `moves` `noMirror` `animationWeights` `animGap` `confineToScreen`（窗口与手感）、
`basketball`（投篮小游戏）、
`font` `events` `eventsRefreshSec` `workStatusTexts` `memes`（说话与联动）、
`dsh`（含余额直连参数）、`session`（会话日志观察）、`ai`（本机模型）。
**动画素材清单仍然不在配置里**，播什么由 `assets/webm` 的目录名决定（见下）。
文件末尾的块注释只列「仍然没有实现」的字段（聊天记忆轮数、按服务商指定模型等），代码不读。

`confineToScreen` 管多屏抛掷：`false`（默认）= 甩过屏缝就飞到隔壁屏；`true` = 屏缝当墙，
只在松手那块屏内弹。走位永远只在脚下那块屏活动，跟这个开关无关。

### 目录名 = 用途（特殊文件夹）

`assets/webm` 里**某些目录名有特殊含义**，把素材放进去就自动获得对应行为，不用改任何配置。
其余素材统统进「随机小动作池」。

| 目录 | 作用 | 说明 |
| --- | --- | --- |
| `待机/` | 闲着时循环播 | 放一个就固定播；多个则随机、不连续重复 |
| `转向/` | 自己换朝向时播 | **播完会把朝向翻过去**，素材必须是「转过身」的动画 |
| `拖拽/` | 被拎起来拖动时播 | 应该是脚离地的悬空姿势 |
| `走位/` | 自己挪动时播 | 一次播完 = 走一段路；距离/首尾停顿在 `config.jsonc` 的 `moves` 里调 |
| `点击回应/` | 左键点一下时播 | 随机抽一个，放几个就随机几个 |
| `余额/` `碎碎念/` | 特定剧情 | 不参与随机：由事件触发（余额六档 / 定时碎碎念），也能从菜单点播 |
| 其它所有目录 / 根目录 | 随机小动作池 | 空闲时随机抽，是桌宠「自己动」的主要内容 |

三条规则：

- **目录名在任意层级都认**：`待机日常/待机/x.webm` 同样算待机。所以可以把特殊素材收在分类目录里，不影响归类
- **一个文件只属于一个目录**，所以「既要随机播、又要被点一下播」做不到，除非复制一份到两个地方
- **加一个素材不用改配置**：扔进 `走位/` 就是走位动作，参数自动取 `moves.default`；
  想给它单独调参数，才去 `moves.actions` 里按文件名加一条

`moves` 里那几个参数的含义：

```jsonc
"moves": {
  // 所有走位动作共用
  "default": { "minDist": 60, "maxDist": 240, "margin": 20, "leadSec": 2, "tailSec": 2 },
  // 只写要覆盖的键，没写的取 default
  "actions": [
    { "name": "原地左转奔跑", "params": { "minDist": 120, "maxDist": 320, "leadSec": 1.75, "tailSec": 4.8 } }
  ]
}
```

| 键 | 含义 |
| --- | --- |
| `minDist` / `maxDist` | 单次行进距离 px（以 462 宽为基准，按实际大小等比缩放） |
| `margin` | 贴边安全距 px（不随缩放） |
| `leadSec` / `tailSec` | 动画首尾各多少秒原地不动（起跑蓄力 / 停下收势） |

### 右键菜单里的动作列表

「动作」子菜单**照搬 `assets/webm` 的目录树**，最前面多一块注入的「表情包」子菜单（见 2.2）；
用途约定和菜单层级互不干扰 —— 菜单显示全部目录，用途只看目录名。每次右键都重扫，丢文件、建目录都不用重启：

```
动作 ┬ 说明 · 我的动作总览    ← 根目录放了 .md 就显示（灰色不可点，悬停看全文）
     ├ 走路                    ← 根目录的素材直接平铺
     ├ 小动作 ┬ 说明 · 站着不动的动作
     │        ├ 悠闲哼歌
     │        └ 深层 ─ 超大伸懒腰   ← 多深都行
     └ 情绪 ─ 生气
```

- **目录名 = 菜单层级**，想怎么分类就怎么建目录；根目录的文件平铺显示
- 文件名的 stem = 菜单条目；播放键是「子目录/名字」，不同目录里的同名文件不会打架
- **目录说明**：往目录里放一个 `.md`（推荐 `说明.md`，也认 `README.md` / 任意 `.md`、`.txt`），
  第一行当标题、全文当悬停提示，显示成该子菜单顶部一条灰色不可点条目。`.md` 不会被当成素材，也不影响播放
- 同一层超过 30 个文件会自动按序号分页（`1 - 30` / `31 - 60`）—— 想避开就自己分目录
- 目录里没有 webm 的不会显示（只写了说明的空目录也一样）
- 从菜单点播 `走位/` 里的动作会走完整一次走位（不是原地踏步）；点播 `noMirror` 里的文字动画
  会先把宠物掰回朝左，免得字是反的

## 2. 说话、表情包与事件联动

这几块原本都是 DSH 插件里的功能，独立版把它拆成「素材 + 数据源」两层：素材全在
`assets/` 里，数据源有就用、没有就降级，**不会因为缺环境起不来**。

### 2.1 文字气泡

宠物头顶的白底圆角气泡，尾巴指着脑袋。字号默认按宠物宽度算（`宽度 × 0.0455`，462px 的宠物
约 21px），字体用 `assets/fonts/上首软糖体.ttf`。气泡是独立分层窗口且**不吃鼠标**
（点气泡等于点穿到下面的东西），跟着宠物走动，到点自动收。

`config.jsonc` 的 `font`：`family` 留空 = 用自带字体；`size: 0` = 按宠物尺寸自动算（写数字就是固定 px）；
`followPet` = 缩放宠物时字号跟不跟着变。

### 2.2 表情包

`assets/memes/` 里有 27 张随附表情包，**文件名就是 `memes` 配置里的键**。那句描述有两个用途：
右键菜单的悬停提示，以及给模型挑图时的候选清单。

```
右键 ┬ 动作 ┬ 表情包 ┬ 随机一张（共 27 张）
     │       │        ├ Ciallo            （比耶眨眼卖萌问候 Ciallo～…）
     │       │        └ 可爱              （标准正面卖萌立绘…）
     │       └ 小动作 / 情绪 / …          ← 动画目录（表情包永远排最前）
     ├ 大小 ┬ 小 / 中 / 大…（预设 px）
     ├ 固定原地（不自己走、不自己转身）
     ├ 投篮游戏（开局后变成「结束投篮游戏（N 分）」）
     ├ 回到初始位置
     ├ 重载配置
     ├ 碎碎念 / 说句话… / 刷新余额        ← 平铺在根菜单，不用进子菜单
     ├ 再来一只
     └ 退出 / 关掉这只             ← 只剩一只时是「退出」，多只时只关当前这只
```

加图：png 丢进 `assets/memes/`，在 `config.jsonc` 的 `memes` 里补一行 `"名字": "描述"`。
**只换图不用改配置**。有模型时（DSH 或本机），碎碎念/对话会顺手让模型挑一张配上 —— 挑不出来就只说话。

### 2.3 数据源，优先级从高到低

| 数据源 | 提供什么 | 怎么启用 |
| --- | --- | --- |
| **会话日志** | 工作状态（想/做/等你点头/等你回答）、完成与出错提醒、交付提醒 | 什么都不用配：dsh 登录过、`$DSH_HOME/sessions` 里有日志就行（见 2.6） |
| **DSH** | 工作状态、通知、点播动画、用 DSH 配的模型说话 | 装了 DSH 且 dsh-pet 插件在跑（自动探测 `127.0.0.1:3080`） |
| **本机模型** | 说话（碎碎念 / 对话 / 挑表情包） | `config.jsonc` 的 `ai` 填 `baseUrl` + `model`（OpenAI 兼容） |
| **纯本地** | 只播动画，不弹文字 | 什么都不用配（默认就是这个） |

**会话日志和 DSH 抢同一件事**（工作状态）：日志那条能读就用它，DSH 的 `workStatus` 自动让位，
免得两个来源轮流打断同一个动画。

**余额不参与这套优先级**：它固定走 `balance.py` 的直连（读本机 dsh 登录凭据问 DeepSeek
Platform），跟 DSH 有没有启动毫无关系 —— 只要凭据在就一直能查（见 2.5）。

启动时日志会告诉你落到了哪一档：

```
[会话] 观察 C:\Users\你\.dsh\sessions（zstandard 解压）
[dsh] 已连上 http://127.0.0.1:3080（DSH 桌宠插件在跑）
[dsh] 没找到 DSH（跳过工作状态/通知/DSH 说话，纯本地模式）
[余额] 直连可用（凭据 C:\Users\你\.dsh\.credentials.yaml），不看 DSH 在不在
```

### 2.4 DSH 对接

原插件把能力挂在 **DSH 自己的 Web 服务**上（`dsh web`，默认 `127.0.0.1:3080`），前缀
`/dsh-pet-7340`，**只监听本机、没有鉴权**，所以这个独立版不需要 Node / Electron，
直接按上游 [`openapi.yaml`](https://github.com/PC2005-cloud/dsh-pet/blob/main/openapi.yaml) 说 HTTP：

| 用到的接口 | 干什么 |
| --- | --- |
| `GET /state?since=&timeout=` | 长轮询：工作状态 / 通知 / 说话 / 点播动画 / 占用锁 |
| `POST /whisper`、`POST /chat` | 用 DSH 配的模型说一句 / 对话（回复可带配图名） |
| `POST /pose/report` | 把桌面宠物的位置和朝向报给 DSH（网页端与第三方能读到） |

上游还有个 `POST /balance`，本版**不调用**（状态里的 `balance` 叶子也不订阅）——
余额统一走 2.5 的直连，省得同一个数字出现两套口径。

探测顺序：`dsh.baseUrl` → 环境变量 `DSH_PET_URL` / `DSH_WEB_URL` / `DSH_URL` → 默认 3080。
**探测不到就整块关掉**：不请求、不占线程，只在启动日志里说一句（**菜单里不再显示 DSH 状态行**），
余额照旧能用。
`dsh.enabled = false` 可以连探测都省掉。

状态比对沿用上游口径：每个叶子带 `counter`，**变了才算更新**；首拉只记基线不渲染，
所以不会一启动就把上次留下的余额动画重播一遍。收到第三方的**占用锁**时宠物冻结自播
（不掷骰、不走位），显式点播和拖拽照常。

### 2.5 余额：只有一条通道，跟 DSH 启不启动无关

余额**不看 DSH 在不在**，也不走它的 `POST /balance`。原因很简单：余额数据本来就躺在磁盘上，
没必要为了看一眼余额去拉起一个服务，更没必要在两个数据源之间切来切去、让同一个数字有两种口径。

| 通道 | 什么时候用 | 需要什么 |
| --- | --- | --- |
| **直连** DeepSeek Platform（唯一） | 一直用，DSH 在不在都一样 | 本机登录过 dsh（有 `.credentials.yaml`），**不需要 dsh 在跑** |

直连原理（全在 `balance.py` 一个文件里）：dsh 登录后凭据就明文存在
`$DSH_HOME/.credentials.yaml` 的 `records."deepseek-account-platform/default".payload` 里，
带上那个 token 请求 Platform 的 `get_user_summary` 就能拿到钱包余额 —— 不启动服务、
不交换 cookie、零第三方依赖。

右键 →「刷新余额」（根菜单上，直接点）手动查一次；`eventsRefreshSec.balance` 到点也会自动查
（`balance_ready` 只看凭据在不在）。**把鼠标停在「刷新余额」上**，悬停提示就是最近一次查到的结果。
结果落到气泡 + 六档钱袋动画：

```
余额 ¥12.35（含赠金 ¥2.00） · 累计花了 ¥87.65
```

| `dsh` 段的配置 | 默认 | 说明 |
| --- | --- | --- |
| `balanceFull` | `100` | 参考额度（¥）：余额到这个数算「钱袋满溢」，用来折算百分比；填 `0` = 只弹数字、不播动画 |
| `balanceHome` | `""` | dsh home 目录；空 = `$DSH_HOME` 或 `~/.dsh` |
| `balanceTimeout` | `30` | 单次请求超时（秒） |

开关只有两个：`events.balanceEnabled`（要不要这个功能）和凭据文件在不在。
读不到凭据就不显示余额入口，日志会说一句「[余额] 读不到 dsh 登录凭据」。

⚠ **凭据等同密码**：只读 token 用于请求，不打印、不写日志、不进仓库。
token 失效（HTTP 401 / `code=40003`）时气泡会直说「请在 dsh 里重新登录」。

`balance.py` 也能单独当命令行用（`python balance.py --watch 300`），
桌宠这边只是把同一份函数当库调。

### 2.6 会话状态：从日志里看出它在干什么（`session.py`）

DSH 的 `workStatus` 只在插件推的时候才有，粒度也粗。这条路更直接：**读 dsh 自己写的会话日志**
（`$DSH_HOME/sessions/*/session-*/session.*.jsonl.zstd`，append-only，增量解压），
不需要联网、不需要 dsh 在跑、不要任何令牌。

`session.py` 上半部分负责「读日志 → 折叠状态」（`idle / thinking / tool / waiting_approval / waiting_answer`，
外加工具名、待办进度、交付文件、后台任务）；下半部分负责**什么时候把它变成反应**。

| 日志里看到的 | 桌宠的反应 |
| --- | --- |
| 开始干活（闲 → 想/做） | `工作状态-思考冒泡`，气泡「开工啦～」 |
| 在调工具 | `工作状态-忙碌点按`（不弹气泡，免得每一步都念一句） |
| 在整理上下文（compaction） | `工作状态-清点归档` |
| 等你点头 / 等你回答 | `工作状态-原地踱步张望` + 「要动 Bash，等你点头」 |
| 这一轮完成 | `工作状态-雀跃庆祝` + 「干完了」 |
| 出错 / 被中止 / 被截断 / 后台任务挂了 | `工作状态-垂头叹气冒汗` + 日志里那句原因 |
| 交付了文件 | `工作状态-雀跃庆祝` + 「交付了 xxx」 |
| 回到闲（没有 turn/end，比如进程崩了） | 安静回待机，不弹气泡（`staleSec` 兜底） |

#### 难点在这：什么时候触发

日志一秒能来好几条，全播一遍就是幻灯片。所以规则按优先级是这样（代码里 `ReactionPolicy`
顶部的注释是同一份）：

1. **只认跃迁，不认状态本身。** 按 `(会话, status)` 是否变化触发。同一个状态持续再久也不会
   重复播 —— 这是不刷屏的根本。
2. **忙碌内部抖动要合并。** 一轮任务里 `thinking ↔ tool` 随每一步来回切（一次工具调用切两下），
   所以这两个状态之间切换要**稳定 `minHoldMs`（默认 1.2s）才认**；而**从闲进入忙碌立即反应**
   （那是主人真的按了回车）。`waiting_*` 永远立即反应，主人在等它，不能等。
3. **启动/换会话只对齐，不复读。** 首次拿到快照时，状态是「当下正在发生的事」，值得立刻把
   动画切过去；但它是历史，**不该弹气泡**（否则一开程序就被念一句）。主会话被别的会话抢走时
   也静默换动画。
4. **一次性事件走 notices。** 完成/出错/中止/截断/审批/后台任务/交付 —— 日志里这些是「发生了一次」
   的事件，读日志那一半已经做了首次静默 + 增量消费，这里照单播一次。同一批来的几条合成一句。
5. **久等/久忙才催，而且有上限。** 等主人超过 `waitNudgeSec`（25s）开始催，之后每
   `waitRepeatSec`（90s）一次、最多 `waitNudgeMax`（3）次；一直忙超过 `busyNudgeSec`（3min）
   说一句，最多 `busyNudgeMax`（2）次。**叫不动就不叫了** —— 桌宠的价值是「在场」，不是「催命」。
6. **会挑主会话，并且粘住。** 几个会话同时开着时按「等主人 > 忙碌 > 空闲，再按最近活动」排序；
   同档次时**粘住当前这只**，免得两边一齐动、宠物在中间反复切状态。

两个细节：

- **催的计时从「我们确认这个状态」算**，不是从日志里的 turn 开始算 —— 刚启动就接手一个跑了
  十分钟的会话，不会立刻被念一句；而且忙碌内部一切换就清零，它在动说明没卡住，不催。
- **动画是「持续」的**：`工作状态-*` 播完会自动重播（`PetWindow.set_status`），不会播一遍就
  回去发呆；拖着宠物或把它甩飞时先记着，落地再补上。

配置在 `config.jsonc` 的 `session` 段，参数全是上面这些时机：

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 关掉就完全不读日志 |
| `home` | `""` | dsh home；空 = `$DSH_HOME` 或 `~/.dsh` |
| `pollMs` | `1500` | 多久看一次日志（增量读，大文件也不怕） |
| `staleSec` | `600` | 多久没新事件就认定这一轮结束了 |
| `minHoldMs` | `1200` | 「想 ↔ 做」抖动窗口 |
| `bubble` | `true` | `false` = 只播动画不说话 |
| `waitNudgeSec` / `waitRepeatSec` / `waitNudgeMax` | `25` / `90` / `3` | 等主人的催促节奏 |
| `busyNudgeSec` / `busyNudgeMax` | `180` / `2` | 忙太久的提醒节奏 |
| `maxSessions` | `8` | 最多同时盯几个会话 |
| `texts` | 内置几句 | 跃迁时说的话（notice 类用日志里现成的文案） |

当前主会话的即时状态（`干活 · Bash · 24s · 待办 2/5 · @项目名`）走气泡，**菜单里不再占一行**。

`session.py` 也能单独跑：`python session.py`（主会话一行）、`--all`（所有活跃会话）、`--json`（完整快照）、`--watch 2`（变化时输出）。
依赖 `zstandard`（已在 `requirements.txt`）—— 没装的话这条路会自己关掉，只留 DSH 那条。

### 2.7 事件怎么落到素材上

不用配池子，按**名字**找（和上游 config.jsonc 的池子同名，仓库里的素材就是这么命名的）：

| 事件 | 素材 | 气泡 |
| --- | --- | --- |
| 余额 0 / 20 / 40 / 60 / 80 / 100% 六档 | `余额-钱袋满溢` … `余额-分文不剩` | 钱包可用余额相对 `balanceFull` 折算，显示余额 + 赠金 + 累计花费 |
| 会话状态 想/做/整理/等点头/等回答 | `工作状态-思考冒泡 / 忙碌点按 / 清点归档 / 原地踱步张望` | 见 2.6（跃迁时才说，notice 用日志里的原文） |
| 工作状态 thinking/working/result/waiting/success/error（DSH 那条） | `工作状态-*` | `workStatusTexts` 每档随机一句 + 任务名；**有会话日志时自动让位** |
| 通知（完成 / 失败 / 被截断 / 申请权限 / 等回答） | `pic/notify-*.png` 小图标 | 标题 + 80 字以内正文 |
| 碎碎念 | `碎碎念-擦桌碎碎念 / 发呆碎碎念 / 对屏碎碎念` | 模型生成的那句话 |

余额百分比口径：**直连固定产出 `money` 形状**，按钱包可用 / `balanceFull` 折算，所以档位只跟这个比值走。
`windows` / `points` / `custom` 是给 DSH 或第三方数据源留的形状，`events.py` 仍然认，但本版没有入口。
给不出语义就只弹文字、不播档位动画。
素材被删/改名也不会报错，那一档就跳过。

### 2.8 定时器

`eventsRefreshSec`：`whisper` 默认 300 秒、`balance` 默认 1800 秒。没有模型时碎碎念
**不会真的发请求**（只保留手动触发）；余额只要有本机凭据就会按时查，跟 DSH 状态无关。

### 2.9 点击音效 / 拖拽光标

`events.clickSoundEnabled = true` 打开点击音效（`assets/sound/click-duck.wav`，
100ms 内连点只响一次，多开不叠音）。拖拽时换成 `pic/cursor-grab.png` / `cursor-grabbing.png` 抓手光标。

### 2.10 投篮小游戏（`basket.py`）

右键菜单 → **投篮游戏** 开局：筐出现在宠物**另一边**（宠物在屏幕左半边就出右边，反之出左边），
朝向也会自动镜像让篮口朝着屏幕内侧，宠物头顶出现 `分数 0`。把宠物当球甩出去，
**飞行途中**身体中心穿过筐口判定圈就计分，头顶飘 `+10`、筐口扩一圈波纹，
宠物「嗖」地回到这一投的起点并播一段庆祝。

```
宠物（球）         筐
  ◯  ──甩出──►   ◎ ← 筐口判定圈：中心 20% 满分，往外线性降到 1 分
```

- **筐可以拖**：左键按住拖到桌面任何位置；**右键筐** = 分数 / 最高分 / 回到宠物旁边 / 结束投篮游戏。
  游戏开着时宠物菜单里那项也会变成「结束投篮游戏（N 分）」，两处都能收
- **计分**：判定点取身体中心（`physics.body_box` 那套 640×360 比例），判定半径 = 筐口内径 × `hitRatio`。
  `u = 距离 / 判定半径`：`u≤0.2` 给 10 分，`0.2~1.0` 线性降到 1 分，`u>1` 没进
- **扫掠判定**：每帧拿「上一帧中心 → 当前帧中心」的线段跟判定圆求最短距离，
  一帧能飞十几像素，只判当前帧会漏掉高抛球
- **按最近距离结算**：进圈后先记这一路「离筐心最近多远」，等它飞出圈（或落地）才结算。
  拿入口那一点算的话，正穿筐心的球也会因为入口在边缘被判成 4 分（实测过）
- **一投只计一次**：甩出 → 落地静止算一投；半路被抓住/被别的宠物撞飞也算这一投结束
- **命中回位**：进了就把宠物送回**这一投的起点**（甩出去那一刻的位置），默认落地/命中后 220ms 生效。
  命中后不等它落地弹跳完（撞墙能耗好几秒），直接收掉飞行再回去；这 220ms 里你要是又把它抓起来了，
  就不抢鼠标、让它跟着手走。庆祝动作跟回位一起播，不会播两遍
- **游戏期间不乱跑**：`window.set_game_lock(True)` 让随机链只播待机，投完立刻可以再抓；
  关掉游戏就恢复原来的随机动作
- **最高分**：存在 exe 同级的 `basket-score.json`（`{"best": 17}`），破纪录才写盘；删掉就清零
- 只认**开局的这一只**，别的宠物扔进去不算分；多开时开新局会先把上一局收掉

换图：把图丢到 `assets/pic/basket.png`（或改 `basketball.image`），下次开局就用图，
占位蓝框和「篮筐·占位」字样自动消失。
**图要求是正方形**——窗口边长恒等于 `width`，方形图直接等比缩到 `width` 见方；
万一给了长方图也不会拉伸，按比例缩进方框居中、四周补透明（等于小一圈）。
**透明白像素点不到**（窗口用 alpha 遮罩，只有不透明的地方吃鼠标），所以图别留大片空白边。

**朝向自动镜像**：原图默认「篮板在左、篮口朝右」。筐被拖到屏幕**右半边**时自动左右翻转，
让篮口朝着屏幕内侧（也从宠物那侧看得到网）；**拖动过程中每移动一帧都重新判断**，
拖过屏幕中线就当场翻、拖回来当场翻回，松手不用再动一下。
所以 `mouthX` 永远按**原图**量，代码在镜像时自动取 `1 - mouthX`，判定圈不会跟着错位。
中线附近留 6px 余量（`FLIP_DEADBAND`），慢慢拖过去不会来回抖。
拖动期间点选区域取两个朝向的**并集**（`_mask_drag`）：翻转只换画面、不改区域，
否则 Windows 上区域一变鼠标抓取会断，表现就是「拖到中线就卡住不跟手」。

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 关掉后菜单项点了没反应 |
| `image` | `assets/pic/basket.png` | 找不到就画蓝框占位 |
| `width` | 240 | 篮筐窗口**边长**（窗口恒为正方形；图片要求也是正方形） |
| `mouthRatio` | 0.47 | 筐口内径 / 窗口宽度 |
| `mouthX` / `mouthY` | 0.615 / 0.522 | 筐口中心在**原图**里的位置（0~1；镜像时自动取 `1-mouthX`） |
| `hitRatio` | 0.9 | 判定半径 / 筐口半径（越小越难；画面缩到 240 后提到 0.9，判定半径仍 ~51px） |
| `perfectRatio` | 0.28 | 满分圈 / 判定半径 |
| `badgeOffset` | 8 | 分数徽章离头顶再往上多少 px |
| `celebrateAnim` | `点击回应/点击回应-开心跃动` | 命中落地后播的动作（留空就不播） |
| `returnHome` | `true` | 命中后回到这一投的起点 |
| `returnDelayMs` | `220` | 命中后多久回去（0 = 进筐立刻回位） |
| `showRings` | `false` | 换成真图之后还想看判定圈就打开 |

### 2.11 对话输入框（`saybox.py`）

右键 **说句话…** 不再弹 `QInputDialog` 那种系统灰框，而是在**宠物右侧**冒出一条自绘输入框：

- 观感和头顶气泡同一套比例（白底半透明、圆角 `0.77×字号`、深灰字），多一层极淡投影 + 1px 描边
- **回车发送**（`returnPressed` → `chat()`）、**Esc 收起**、空文本回车等于取消
- 位置：宠物右侧 5px，竖直对齐「头顶线」（`top + width*0.108`，和气泡是同一条线）；
  右边塞不下就整条翻到左边，**尾巴跟着换到右侧**指向宠物
- 跟着宠物走：挂进 `window.followers`，宠物走位/被拖/被甩时输入框一帧不落（和计分徽章同一套机制）
- 焦点：打开时 `activateWindow()` + 输入框 `setFocus`；焦点跑到本程序别的窗口就收起，
  整个程序被 Alt+Tab 切走则保留（免得把写了一半的字丢掉）
- 收尾：`events.close_saybox()` —— 托盘隐藏、关掉这只、重载配置、退出都会调

为什么不用 `WindowTransparentForInput`：气泡是「不吃鼠标」的展示层，这个要真的接收键盘，
所以它必须能激活并获得焦点。占位提示语是自己用浅灰画的（走样式表时
`QPalette.PlaceholderText` 会被 sheet 的 `color` 吃掉，提示语会跟正文一样黑）。

## 3. 生成素材

最省事的用法：**把 AI 生成的绿幕视频丢进 `video/src/`，跑 `python make_pet_webm.py`。**

脚本会先报清单，再只做没做过的：

```
------------------------------------------------------------------
 源目录   F:\OTHER\dsh-pet\video\src（递归 2 层子目录）
 输出到   F:\OTHER\dsh-pet\assets\webm（工程素材目录 assets/，源码模式直接读）
 视频总数 12
 已生成   9（跳过）
 待生成   3
 成品位置 7 个落在子目录里（沿用源树的目录结构，缺的目录会新建）
 新建目录 2 个：吃吃喝喝、节令
 去水印   开 · watermark_mask_v5.mkv
 并行     4 个进程
------------------------------------------------------------------
 跳过：待机呼吸休闲、悠闲哼歌 …
 落点提醒：1 个成品直接落在根目录 → 会进「随机小动作池」
          想让它们归到待机 / 转向 / 拖拽 / 走位 / 点击回应，
          就在 video/src 里建同名子目录再放进去，成品会镜像过去。
```

转码比较久，跑的时候终端上有一行原地转圈的进度（不刷屏，也不会和结果行搅在一起）：

```
 | 已完成 3/12 · 已用 01:24
```

每做完一个就落一行定格结果，转圈行自动擦掉重画：

```
[1/12] 吃饺子.mp4  OK  120帧  3.4MB  21.3s  站立402px→267px
[2/12] 挥手.mp4    OK   48帧  1.1MB   9.8s  站立380px→267px
```

报的是**完成数**而不是「正在做第几个」—— 4 个进程并行时本来就同时在做 4 个。
输出被重定向到文件或管道时（不是终端），转圈会自动关掉，只留每行结果。

### 源目录也支持分类目录树

`video/src/` 底下可以随便建子目录，**成品会镜像到 `assets/webm` 的同名子目录**，缺的目录自动新建：

```
video/src/                          assets/webm/
├── 吃吃喝喝/                        ├── 吃吃喝喝/
│   ├── 吃饺子.mp4        ──────►    │   ├── 吃饺子.webm
│   └── 节令/                        │   └── 节令/
│       └── 吃青团.mp4    ──────►    │       └── 吃青团.webm
└── 平铺在根上的.mp4      ──────►    └── 平铺在根上的.webm
```

所以「生成」和「分类」可以一步做完 —— 在源目录里就把文件夹分好，双击一次，菜单里直接就是那个结构。
反过来也成立：完全不建子目录，成品照旧平铺到 `assets/webm` 根（老用法不变）。

`assets/webm` 里的目录**只增不减**，废弃的素材自己删。

**增量规则**：递归扫 `assets/webm`（含所有子目录）里已有的成品，按文件名对上就跳过；
只有源文件比成品新时才重做。所以反复双击是安全的，只会补新加的。
成品被手动挪到别的分类目录也照样认得出，重做时**写回它原来那个位置**，不会在镜像位置多留一份。

成品**直接写进工程的 `assets/webm`**，不用再 `--deploy` 或手动复制。宠物跑的是源码的话，下次点开
右键菜单就能看到新动作（菜单每次都重扫目录）；如果 `dist/assets` 已经存在，脚本还会顺手把新成品
同步一份过去，省得为了一个动作重跑打包（`--no-sync` 可关）。

输出文件名 = 动画名。**成品落在哪个目录才决定它怎么被播**（`待机/` `转向/` `拖拽/` `走位/` `点击回应/`，
见上一节），所以想要自动行为正确，就在 `video/src` 里建同名子目录再放视频；直接丢在根上的
成品会进「随机小动作池」，脚本会在清单下面提醒你几个落到了根目录。

| 参数 | 说明 |
| --- | --- |
| `--src` | 换个源目录（默认 `video/src`；拖文件夹到 `.cmd` 上等价）。支持多层子目录 |
| `--out` | 换个输出目录（默认 `assets/webm`，一般不用改） |
| `--no-sync` | 不把成品同步进 `dist/assets`（默认会同步，前提是那边已有素材目录） |
| `--force` | 已有成品也全部重做 |
| `--mask` | 水印遮罩，默认 `video/watermark_mask_v5.mkv`（必须和源视频同分辨率） |
| `--no-watermark` | 素材本身没水印时跳过 |
| `--grow` | 水印遮罩的基础外扩像素，默认 4；边缘那圈半透明部分会自动补长，一般不用动 |
| `--jobs` | 并行进程数，默认 4 |
| `--only` | 只处理相对路径含该子串的视频（可以写目录名，比如 `--only 吃吃喝喝`） |

命令行等价写法：

```bat
.venv\Scripts\python.exe make_pet_webm.py
```

工具做四件事，全在一条管线里，不落中间文件、不需要装 ffmpeg：

1. **去水印** — 两条路并用：① 按 mask 定位（逐帧遮罩），先外扩几 px 吃掉半透明边缘、
   再沿「偏离底色」的像素自动长到位，最后用上下左右最近的干净像素做插值填平；
   ② mask 没盖到的地方（比如豆包在**左上角**另打的那串字）自动识别：亮、没有颜色、
   扁长的小块、且不在角色身上 → 直接判透明
2. **绿幕抠像** — 只认「色相 70~170° + 饱和度 ≥0.07 + 明度 ≥0.15 + 绿通道占优」为背景，蓝、白、红不会被误抠。
   饱和度下限比上游低，是因为绿幕被角色光晕提亮、或水印填成淡绿之后饱和度会掉到 0.10 上下——
   卡在 0.15 就会留下一圈灰白边和右下角一片灰白点。「绿通道占优」是配套护栏：白/浅灰角色也低饱和，
   但绿不是它们的最大通道，所以不会被啃
3. **归一化** — 用首尾各 5 帧量站立高度/水平中心/脚底，统一缩放到 640×360，站立 266.7px、脚底 y=330
4. **转码** — VP9 / yuva420p / CRF 40 / 24fps

素材放在 C 盘、D 盘也都能处理，用 `--src` 指过去就行；只是**路径要带引号**，别带末尾反斜杠。
（感觉「目录不存在」时，看脚本打印的三条排查提示。）

## 4. 做一只自己的桌宠

1. 用 `prompts/桌面宠物 10 秒动作提示词.md` 里的配方生成绿幕视频 —— **「通用前缀」那一段不能改**，绿幕纯色、角色居中、双脚锚定、首尾是标准站立，全靠它保证下游能对齐
2. 全部丢进 `video/src/`（顺手建好分类子目录，比如 `video/src/吃吃喝喝/吃饺子.mp4`），
   跑 `python make_pet_webm.py` —— 成品直接写到 `assets/webm/吃吃喝喝/吃饺子.webm`，不用再复制
3. **右键菜单立刻就有**：素材进了 `assets/webm` 就算完事；分类完全靠目录，自己建子目录即可
   （`assets/webm/小动作/悠闲哼歌.webm` → 菜单里就是「小动作 → 悠闲哼歌」）；
   想在某个分类上写点备注，就在那个目录里放一个 `说明.md`
4. **归类靠目录名**，不用碰配置 —— 想让宠物自己动起来，至少准备这几样：
   - `待机/` 放 1 个（最小可跑就是这个）
   - 想完整一点：`待机/` + `转向/` + `拖拽/` + `点击回应/` + `走位/` 各 1~3 个（约 6 个素材）
   - 剩下的素材随便放哪个分类目录，都会进「随机小动作池」——它是桌宠自己晃来晃去的主要内容，
     素材越多越不重复
   - 特殊用途的目录名见上面那张表，**改名就等于改语义**（把 `待机/` 改成 `站着/`，待机就没素材了）
5. 走路路远路近、起跑收势的时长，去 `config.jsonc` 的 `moves` 调（这是唯一还需要配置的动画参数）
6. 右键「重载配置」

配比看 `animationWeights`（待机/转向/走位三档的掷骰权重，余下的概率给随机小动作）；
`fixedEnabled: true` 的宠物不会自己翻朝向、不会自己走动。

两次动作之间会歇一段随机时间（`animGap`），不再一个接一个赶场。间隔 = 随机区间 + 动作后加长
+ 偶尔发呆，**再乘上当前 CPU 占用**（机器忙的时候宠物更安静）。这段空档会**接着播待机动画**
（循环，直到时间到了才切下一个动作）—— 动作视频都要求首尾回到标准站姿，所以从末帧切进待机是平滑的，
看着像站着等你，而不是画面卡住。想更快/更慢改 `minMs`/`maxMs`，
想恢复原来的无缝连播写 `"enabled": false`。

## 5. 打包成可执行文件

```bat
.venv\Scripts\python.exe build.py            :: 目录版 dist\DshPet.exe（推荐）
.venv\Scripts\python.exe build.py --onefile  :: 单文件 dist\DshPet.exe（启动慢，体积集中）
.venv\Scripts\python.exe build.py --console  :: 带黑窗口，能看实时日志
.venv\Scripts\python.exe build.py --clean    :: 先清 build/ 和 dist/ 里的旧构建件（素材会重新镜像）
```

`build.py` 只做编译：镜像素材 → 抠图标 → PyInstaller → 搬到 `dist/` 根。
它**不会替你装 PyInstaller**（缺了会直接告诉你那条 pip 命令）。

产物**直接平铺在 `dist\` 里，没有 DshPet 那一层**，配置和素材都摆在 exe 旁边，不塞进包里：

| 文件 | 说明 |
| --- | --- |
| `DshPet.exe` | 双击启动，无控制台 |
| `_internal/` | Qt / PyAV / numpy 等运行时 |
| `config.jsonc` | 直接改，右键「重载配置」生效 |
| `assets/` | 素材全在这（webm / memes / pic / sound / fonts），换素材不用重新编译 |
| `dsh-pet.log` | 打包版没有控制台，日志写在这里 |

也就是说 **`dist\` 整个目录拷给别人就能跑** —— 它是自洽的，不依赖工程根的任何文件。

打包时**素材是从工程 `assets\` 镜像过去的**，不是原地沿用：
PyInstaller 的产物先落到 `build\pkg\`，最后只把 `DshPet.exe` + `_internal\` 搬到 `dist\` 根。
镜像规则是「缺的/变了的拷过去，`dist\assets` 里多出来的删掉」，所以

- 删了素材 → 下次打包 `dist\assets` 里也不会剩；
- 改了素材忘了重新打包 → 下次打包会自己对齐，不会悄悄停在旧版本；
- 只改代码 → 素材不重拷（大小和修改时间都一样就跳过），打包不会因为 60MB 素材变慢。

`--clean` 不会单独删 `dist\assets`：它下一步会被 `assets\` 重新镜像，删了只是白白多拷一遍
（真要清干净，直接删整个 `dist\`）。
老布局的 `dist\DshPet\`（多一层目录）打包时自动收尾：里面的素材在 `assets\` 里都有就整层删掉，
有 `assets\` 缺的文件则保留并提示，不替你删。

- 桌宠开着的时候打包会提示「文件被占用」—— 先从托盘退出再重跑。

首次构建会自动装 PyInstaller。目录版约 148MB（素材 64MB + 运行时 84MB）。
exe 图标取 `assets/webm/待机/` 里第一个素材的首帧（没有待机素材就退到随机池），
生成 `build/pet.ico` 再嵌进 exe；`--no-icon` 可以跳过。构建结束会读回 exe 校验图标是否真的嵌进去了。

注意：`--onefile` 每次启动都要把几十 MB 解压到临时目录，观感上会慢 2~3 秒，素材改动也得重编译 —— 日常用目录版就够了。

## 6. 和原 DSH 插件对照

上游：<https://github.com/PC2005-cloud/dsh-pet>（MIT）。原形态是「DSH 插件（TS，跑在 DSH 宿主里）
+ 网页 overlay + Electron 桌面 Helper」；这里换成「PySide6 桌面程序 + 直接说上游的 HTTP 契约」。

| 原功能 | 独立版 |
| --- | --- |
| 透明窗口 / 动画链 / 拖拽抛掷 / 落地挤压 / 多开 | 已重写（PySide6 + PyAV，零 Node / Electron） |
| 右键动作菜单（目录即分类 + 目录说明） | 已重写；表情包挂在「动作」下，碎碎念/说话/刷新余额平铺在根菜单 |
| 文字气泡（原 `client/bubble.ts`） | 已补回 —— `bubble.py` |
| 表情包 27 张 + 模型选图 | 已补回 —— `memes.py` + `memes` 配置 |
| 余额 / 工作状态 / 通知联动 | 已补回：工作状态读 **dsh 会话日志**（不用 DSH 在跑，`session.py`），余额走 `balance.py` 直连，通知来自 DSH 事件或会话日志 notice |
| 碎碎念 / 对话 | 已补回：DSH 的模型，或本机 OpenAI 兼容接口 |
| 点击音效 / 拖拽光标 | 已补回 |
| 第三方占用锁（联动演出时独占宠物） | 已支持：收到锁就冻结自播 |
| 长轮询 `/state` + counter 增量比对 | 已实现（2 秒长挂，叶子变了立刻到） |
| 设置页（1943 行 React） | 没有 —— 直接改 `config.jsonc`，右键「重载配置」 |
| 网页 overlay（`display: web / both`） | 没有 —— 独立版只有桌面窗口 |
| 第三方菜单项注册（`/menu/item`） | 没有复刻 |
