## 换真图 + 篮筐朝向自动镜像

用户把 `basket.png`（1385×1385，板在左、篮口朝右，带透明边）放进 `assets/pic/`。

**量出来的几何**（原图比例，直接写进 config 当默认值）：
- 篮圈橙色包围盒 x 0.370~0.841 / y 0.495~0.599（左端和板下沿的橙色护垫混在一起）；
  综合目测圆环中心取向 → `mouthX=0.615`、`mouthY=0.522`、`mouthRatio=0.47`（筐口内径/窗口宽）。
- 对照图验证法：把图缩到目标宽、把 candidate 圈画上去导出 PNG 再肉眼看（`.workbuddy/_out_test/basket_check*.png`），
  比算像素快且直观，值得复用。
- 手感参数重定：`width=320`（原 260）→ 筐口 150px；`hitRatio 0.72` → 判定半径 54px（跟原来占位 51px 持平）；
  `perfectRatio 0.28`。

**镜像**：
- `BasketWindow` 构造时预生成 `_pix_flip = image.transformed(QTransform().scale(-1,1))`，
  `_current_pix()` 按 `_flipped` 取；`set_flipped()` 同步重建 `setMask`（mask 必须跟着翻，否则点到透明区）。
- 判定用的 `mouth_rel_x()` = `mouth_x` 或 `1-mouth_x`；`_paint_rings/_paint_placeholder/_paint_ripple` 全部改用它。
- 触发：`showEvent` / `moveEvent` 里 `_auto_flip()` —— 窗口中心落在 `screenAt(center)` 可用区中线右侧就镜像。
  拖过中线自动翻回来。
- **踩坑**：第一次改 `paintEvent` 的替换没匹配上（缩进/换行差异），grab 出来的左右两张图 md5 一模一样才暴露；
  另外 `set_flipped()` 手动调用会被随后 `processEvents()` 里的 `moveEvent → _auto_flip()` 覆盖，
  测试要改**窗口位置**而不是直接调 `set_flipped`。

## 拖动中实时翻转（补）

用户要求「拖拽时也按当前位置动态镜像」。逻辑本来就在 `moveEvent → _auto_flip()`，真正的坑在 mask：
`set_flipped` 里重建 `setMask` 会在拖动途中改窗口区域 —— Windows 上区域一变鼠标抓取会断（且新区域
没盖住光标就彻底不跟手），表现成「拖到中线就卡住」。

- 三份区域缓存：`_mask_plain` / `_mask_flip` / `_mask_drag`（两者 `united()`）。
  `_apply_mask()` 里 `self._press is not None` 就用并集，松手收回当前朝向的精确区域。
  并集区域不变 → 拖动中翻转只是 `update()` 重画，一次 `setMask` 都不发。
- 先按下再切并集（`mousePressEvent` 里 setCursor 前调 `_apply_mask()`）：并集 ⊇ 精确区域，
  光标仍在新区域内，不会丢抓取。右键不动 `_press`，所以仍用精确区域。
- `FLIP_DEADBAND = 6`：`|center.x()-mid| <= 6` 直接 return 保持现状，中线附近慢慢拖不再来回抖。
- PySide6 6.12 的 `QRegion` **没有 `rects()`**，数块数用 `rectCount()`、包围盒用 `boundingRect()`。

验证（离屏合成鼠标事件）：按下后 mask==并集；拖动 5 帧里 flipped 随中线变化、`w.mask()` 全程不变；
松手 mask==镜像区域；拖回左半边翻回且 mask==不镜像区域；中线 ±6 抖动 7 次不翻；
拖到镜像位置后投一球穿心仍 +10（筐心/判定半径跟着翻）。占位模式（无图）mask=整窗矩形也正常。

验证（离屏）：宠物贴左 → 筐在右 + flipped=True，筐心相对窗口 123px（左半）；贴右 → 筐在左 + False、197px；
两侧各模拟一条穿过筐心的线段都 +10；mask 用 `m_plain.subtracted(m_flip)` 判差异（**不能**比 boundingRect，
图片内容外框左右近似对称，翻前后包围盒一样）。

## 篮筐缩小 + 强制正方形

用户要求「不用图片大小渲染、缩小一些、只保证是正方形，以后换图也要求正方形」。

- 删掉 `BasketballConfig.height`（以及 `_basketball()` 里的解析、config.jsonc 的同名键）：
  **窗口边长恒 = `width`**，`resize(width, width)`。以后只有 `width` 一个尺寸旋钮。
- 新增 `fit_square(pix, side)`：方形图直接缩到 side 见方；**非方图不拉伸**——等比缩进方框居中、
  四周补透明（等价"小一圈"），免得以后有人丢张长方图把篮筐拉扁、判定比例全乱。
- 尺寸 320 → **240**（可见部分 244×320 → 183×240，比宠物 462×260 小一号）。R 会跟着缩到 40.6，
  所以 `hitRatio` 同步 0.72 → **0.9**，判定半径仍是 ~51px（50.8），手感不变、只是画面小了。
  这是"缩图不改难度"的配套动作，以后改 width 记得同步折算 hitRatio 保持 R。

验证（离屏）：窗口 240×240、mask 包围盒 (29,0,183,240)、筐心相对 (147.6,125.3)、R=50.8；
长方图 300×150 → 窗口 240×240、mask 包围盒高 120（居中不拉伸）；主程序空心 +10、0.5R 擦边 +7。
