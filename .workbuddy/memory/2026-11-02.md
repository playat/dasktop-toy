原来只有 `{"best": N}` 且**破纪录才写盘**，用户看不到「累计」概念。改成：

- 新 `@dataclass Record`：`best / total / hits / games`；`read_record()` 容错（文件不存在、坏 JSON、
  老格式只有 best、负数或非数字字段都当 0），`write_record()` 整份覆盖写。
- 写盘时机：**开局 +1 games 并写**、**每次命中 += total/hits 并写**（几十字节，不怕强杀）。

- 老文件 `{"best": 112}`（用户 dist 里已有）能被读成 best=112、其余 0；不回溯 total。

  离屏测这条路径要**先改 `main.SCORE_FILE`** 指到 tmp，否则读到的是真实文件（第一次测就踩了）。

## `bash.exe.stackdump` 是什么（工程根出现了一个）

不是 Python 也不是项目的锅：是 **Git Bash（Cygwin/MSYS2）自己的崩溃转储**。bash 收到致命信号
（栈溢出 / fork 失败 / 被 TerminateProcess 强杀时踩到已关句柄）时，cygwin1.dll 的 handler 往
**进程 cwd** 写 `<进程名>.stackdump`（这里 cwd 就是工程根）。里面只有 `0x1800xxxxx` 的地址
（cygwin1.dll 映像基址），**不含命令行**，所以定位不到具体是哪条命令挂的。

高发场景：命令超时被强杀 / 宿主关掉管道 pty。已删该文件，并把 `*.stackdump` 写进 `.gitignore`。
