## 多宠物：命中庆祝要落在「投进的那只」身上

用户反馈「多只宠物时，进框后开心动画应该在当前宠物播」。先查了路由：`_celebrate_now(win)` 本来就带
`win`，三次探针（合成钩子 / 真实 throw 状态 / PetApp 双层）都证明**确实播在投进的那只**，没串台。

真问题在**会被静默丢掉**的几个口子：

1. `_on_shot_land` 里先 `st.celebrate = False` 再判断定时器 —— 回位定时器已排上时标志被清掉；
   虽然当时 `_celebrate_now` 不看标志所以没事，但一旦加上"按标志播"就永远播不出来。
2. `_go_home` 里 `if win.state == "drag": return`，而且清标志在它**之前** → 命中后 220ms 内
   你把宠物又拎起来，这次庆祝就永久消失。
3. `play_effect` 在 `drag/throw` 状态直接 return（不是排队），回位那一下还在飞就丢。

改法：
- `_celebrate_now(win)` 改成**带重试**：读 `self._shots[win]`，`st.celebrate` 为假直接返回；
  宠物 `state in ("drag","throw")` 就 `st.retry`（180ms 单发，`CELEBRATE_RETRY_MAX=12` ≈ 2s）重试，
  落定后 `play_effect` 并清标志。窗口已销毁 / 不在 `wins` 里 → 清标志走人。
- `_go_home`：`home is None` 也别直接 return（照样补播）；drag 分支改成「先排庆祝再说」，
  不再清标志；清标志统一交给 `_celebrate_now` 播成功后做 → 一次命中只播一次。
- `_on_shot_land` 去掉提前清标志，只留「定时器在跑就跳过」。
- `_Shot` 加 `retry/tries`；`stop()`/`detach()`/`_on_shot_start` 连 retry 一起停/清零。

验证 `.workbuddy/_out_test/celebrate_paths.py` 三条路径：
①正常回位 → pet1 播；②回位时被拎着 → 拎着期间空、松手后 pet0 播；③回位时还在飞 → pet1 播。
`multi_pet_basket.py` / `multi_pet_app.py` 回归通过。

注：本地复现时 `_drive_throw` 里塞了假 `ThrowState` 会报 AttributeError，测试脚本的锅，不是代码问题。
