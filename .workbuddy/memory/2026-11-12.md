# 2026-11-12

## 余额「目标计算机积极拒绝」：系统代理指着死端口

**现象**：开 VPN 能查余额，不开就 `[WinError 10061] 由于目标计算机积极拒绝，无法连接`。

**排查**：

- 注册表 `HKCU\...\Internet Settings`：`ProxyEnable=0`、`ProxyServer=127.0.0.1:7890`；
  7890 由 `FlClashCore` 监听（在跑时），`platform.deepseek.com` 国内直连正常（华为云 WAF，60.204.2.x）。
- 用死代理复现：`ProxyHandler({'https':'http://127.0.0.1:1'})` → 报错文案**一字不差**。
- 结论：`urllib` 跟随系统代理，代理软件退出后设置残留/端口没人监听 → 连 127.0.0.1:7890 被 RST。
  **不是 DeepSeek 挂了，也不是 DNS / hosts**（hosts 里只有 docker 那几条）。

**改**：

- `config.py`：`DshConfig.balance_proxy = "auto"`，解析 `balanceProxy`。
- `balance.py`：`_proxy_urls`（auto/system→None，direct/none→{}，其它→补 http://）、
  `_effective_proxy`（getproxies，环境变量优先）、`_is_loopback`、`_refused`（10061/积极拒绝）、
  `_proxy_error`（说人话）、`_build_request` + `_fetch_once`。
  auto 模式：回环代理被拒 → 打印一行提示 → 直连重试一次。
- CLI 加 `--proxy`；`config.jsonc` / README 2.5 补说明。

**踩坑**：第一次重试仍 10061 —— `Request.set_proxy()` 走代理时会改写 `req.host`，
复用同一个 Request 对象重试等于还连那个死代理。改成每次请求 `_build_request()` 新建。

**验证**（`env https_proxy=http://127.0.0.1:1`）：auto → 提示 + 直连成功（拿到真实 40003）；
direct → 直接成功；`https_proxy=http://127.0.0.1:63488`（活代理）→ 走代理、不误降级。

## 追加：默认改直连（渔夫指出「这接口不需要走代理」）

这个接口国内直连就通（`platform.deepseek.com` → 国内 WAF，443 秒连），跟着系统代理纯属自找麻烦。
`balanceProxy` 默认 `auto` → **`direct`**：

- `balance.py`：`_proxy_urls` 空值默认、`fetch_balance(proxy=)` 默认、`--proxy` 默认三处全改；
  文件头注释的配置说明把 direct 写在第一个并注明「默认」。
- `config.py`：`balance_proxy` 字段默认 + 解析兜底（两处 `or "auto"` → `or "direct"`）。
- `config.jsonc`：值改 `"direct"`，注释改成「默认不绕代理」，auto 降为需要代理时的备选。
- README 2.5 的表格与那段「开 VPN 才查得通」的说明同步重写。

auto 的降级逻辑**保留**（非要走代理的网络还能用），只是不再默认启用。

**验证**：`config.jsonc` 解析出 `balanceProxy='direct'`；死代理环境变量
（`https_proxy=http://127.0.0.1:1`）下 `fetch_balance()` 直接打穿拿到 40003（没走降级分支）；
真实凭据跑 `balance.py` → `充值余额 ¥0 赠金 ¥0 累计消费 ¥0.010888`，全程无代理。
