# 2026-11-06

## 宠物一直循环播待机、不换动作

**现象**：日常状态像"卡在待机循环"，很久不切动作。

**根因**：`_play_idle()` 不检查 `player.play()` 的返回值。

- `待机/` 只有 1 个素材（`待机呼吸休闲.webm`，10.04s），而 `_hold_idle()` 用 **loop=True** 播它当等待背景。
- gap 到点 → `_roll_next` 掷到 idle（10% 权重）→ `_play_idle` 抽到的必然是**同一条** →
  `play()` 判「同名且未 finished」直接 `return False`（loop 永远不 finished）。
- 旧码不看返回值，`_gap_timer` 又已经在这轮掷骰时消耗掉 → **再没人起计时器 → 永久待机**。

**修**（`window.py`）：

1. `_play_idle` 失败 → `_idle_then("idle")` 重排（画面本来就是待机，继续等下一个 gap 即可）；
   `_play_action` / `_play_turn` 失败同样补排，别把链路断在那儿。
2. 新增 `_idle_guard`（3s 单次兜底）：`_hold_idle()` 末尾 start，`_schedule_next()` / `_play()` /
   `_start_move()` 一有正经排期或动画就 stop；超时时只在 `state=="idle"` 且非锁、gap 未排时补排一次。
   覆盖所有没预见到的断链。

**实测**（`.workbuddy/_out_test/`）：

- `idle_rhythm.py` 真实配置 26s：idle 4.4s → action 10s → hold 4s → action，节奏正常，无兜底误报。
- `idle_loop.py old`：把 `_play_idle` 换回旧逻辑，能复现长时间停在 idle（`gap=False` 连续 10s+）。
- `game_unlock.py`：开局 → 收局，锁解除后下一轮正常出 action，`gap=True`。

顺带确认素材**全是 10.04s 一条**，所以"纯待机 + 间隔 + 偶发 12s 发呆 + CPU 加成"最坏能到二三十秒，
README 里补了这个换算和两个可调项（`maxMs` / `longPauseMs`）。
