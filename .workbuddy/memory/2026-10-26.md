## make_pet_webm 改造：默认源目录 video/src + 增量跳过 + 清单提示

用户诉求：C 盘里的视频跑脚本报「目录不存在」，希望在**工作区**放个源目录，调用时直接取，
且已经生成过的不要重复生成，并报清楚「几个视频 / 几个已生成 / 总共要生成几个」。

**结论：venv 不限制任何盘符访问**（实测 `.venv/Scripts/python.exe` 能列 `C:/` 27 项）。
「目录不存在」是路径字符串本身的问题，两个最可能的原因：
1. 路径带多余引号 / 末尾反斜杠（Git Bash 下 `"...\"` 会吃掉引号），`is_dir()` 返回 False 只给一句错误。
2. **原来的 `make-webm.cmd` 是 UTF-8 + 中文注释**，cmd.exe 按 cp936 解析 → 中文注释被当命令执行、
   参数被拆坏（实测报 `'㈢殑鍙傛暟缁х画閫忎紶' 不是内部或外部命令`）。**这很可能才是元凶**。
   → 现已改成**纯 ASCII** 的 .cmd（中文提示全部由 Python 打印，Windows 控制台 UTF-16 输出不乱码）。

**改动（`make_pet_webm.py`）**：
- 新增 `DEFAULT_SRC = video/src`；`--src` 变可选，不传就用它（不存在则自动创建）。
- `--src` 传了但不存在 → 打印三条排查点 + 默认目录建议；是文件 / 无权限（PermissionError）分别给提示。
- `_clean_path()`：自动剥引号、首尾空白、末尾 `\`（C1/C2 两种畸形路径实测都能救回）。
- **增量**：输出目录已有同名 webm 且 ≥2KB 就跳过；源文件 mtime 比成品新才重做（`--force` 全做）。
- **清单**：源目录/输出目录/视频总数/已生成/待生成（含"其中 N 个源文件更新"）/去水印/并行，
  外加跳过名单、**命名核对**（`_anim_names()` 从 config.jsonc 捞动画名，对不上的列出来）。
- 汇总：成功数/失败数/用时/输出目录累计数量 + 失败清单。
- `deploy()` 改为返回 `(copied, overwritten)`，输出「覆盖同名旧素材 N 个」——提醒影响面。

**顺手修的性能坑（重要）**：`MaskFiller` 原来取「所有帧 mask 的并集」当水印区，而
`watermark_mask_v5.mkv` 底部有一条横贯全宽的 3px 白线，并集直接变成 1280×720 →
每帧对整幅 92 万像素跑 24 圈膨胀，**24 帧视频要 91 秒**。改成**逐帧紧包围盒**后同样素材 20.8 秒（≈4.4×）。
遮罩实测：白像素只占 0.14%~1.12%，几乎都是一条底边线 + 零散点。

**教训（差点造成损失）**：验证时我拿真实动画名 `悠闲哼歌` 做测试素材，`--deploy` 把
`assets/webm/悠闲哼歌.webm`（584KB 原素材）覆盖成 2.9KB 测试文件，随后清理又把它删了（106→105）。
git 里 0 个 webm（`.gitignore` 早就排除了），**靠 `dist/DshPet/assets/webm/` 的打包副本才恢复**
（106 个逐 MD5 校验一致）。→ 以后测试素材一律用 `_check_only` 这类不可能撞名的名字。

**两个环境坑（都吃过）**：
1. **同一文件多处改动不要并发发多个 Edit**：工具是「读-改-写」，并行时后写覆盖先写，
   会静默丢掉一部分改动（本次 5 处只落地 2 处，且工具全报 success）。
   → 要改多处就写个补丁脚本一次改完（带 `assert count == 1`），或者严格串行。
2. **Git Bash heredoc 会把 `\\` 变成 `//`**（MSYS 路径转换），所以 heredoc 里写含反斜杠的
   路径（`F:/OTHER/...`）永远匹配不上。→ 用 `BS = chr(92)`，或者把补丁脚本写成文件再跑。

### confineToScreen 实现（原本是"配了但没读、行为还被写死成 true"）

原 `_sync_area()` 只在 `_start_throw` / 走位前调一次，等于**抛掷永远锁在松手那块屏** ——
即行为已经是 `true`，而配置默认写 `false`，两边不一致。现在：
- `config.PetConfig.confine_to_screen`（根字段，**不在 physics 里**）← `raw["confineToScreen"]`
- `window.PetWindow._confine`；`_drive_throw()` 里**积分前**调 `_follow_screen()`
- `_follow_screen()`：`screenAt(中心)` 命中就换 area 重算 bounds；返回 None（屏缝/全屏外）
  **保持当前 bounds 不 fallback 主屏**，让这一步先飞完 —— 否则会卡在半空
- 拆出 `_screen_area_at_center()` / `_adopt_area()` 供 `_sync_area` 复用
- 走位仍走 `_sync_area`（锁脚下那块屏），跨屏走位没意义

**验证**（offscreen + patch `QGuiApplication.screenAt` 造假双屏）：中心进副屏 → area 切、
`max_x` 重算正确；`confine=True` 中心回主屏 → area 不动；`confine=False` → 跟回主屏。
抛掷 6 帧积分正常、装配冒烟正常。

## make_pet_webm 加 loading 转圈

转码一个视频 20~90s，原来的输出是「做完一个才打一行」，第一个视频慢的时候屏幕长时间不动，
像卡死。加了 `Spinner` 类（`make_pet_webm.py`），0.1s 一帧原地转圈：

```
 | 已完成 3/12 · 已用 01:24
```

**三个约束（都是踩过的坑推出来的）**：
1. **帧只能用 ASCII `|/-\`**。cmd.exe 默认 cp936，盲文字符（⠋⠙⠹…）不在 GBK 里，
   写出去 `UnicodeEncodeError`，而且 .cmd 里救不回来。
2. **只在 `sys.stdout.isatty()` 时画**。重定向到文件/管道时 `\r` 会把整个日志压成一行。
   非终端时退回「每完成一个打一行」的老行为。
3. **画行和打结果共用一把 `threading.Lock`**，`report()` 里先 `_wipe()`（`\r` + 宽度个空格 + `\r`）
   再 `print`。不锁的话子进程结果一返回就会和转圈行撞成
   `[3/12] OK ... 已完成 2/12` 这种半截串行的乱码。

清行的空格长度取 `shutil.get_terminal_size().columns - 1`，写死会在大/小窗口里擦不干净或自己换行。

**顺手改了并行路径**：`ex.map` → `submit` + `as_completed`。原来按提交顺序返回，
第一个视频慢的时候后面早做完的也得干等，看着更像卡死；现在谁先完谁先报。
子进程整体挂掉（BrokenProcessPool）也接住了，标成 `（子进程异常） FAIL ...` 而不是整个脚本崩。

**文案**：显示「已完成 3/12」而不是「处理中第 3 个」—— 4 个进程并行时本来就同时在做 4 个。

**验证**：单测用 StringIO 强制 `enabled=True` 抓原始字节，确认转了 3 帧、3 条结果前都有 wipe、
无串行；端到端造两个 10 帧绿幕 mp4 走 `--jobs 2` 真实转码，2/2 OK、无 `.part` 残留；
`--only` 匹配不上时不启动转圈。

**README**：生成素材一节补了转圈说明 + 两行示例结果，顺手修了那里一个多余的空代码围栏，
并把过期的「脚本会核对 config.jsonc 里的动画名」换成「成品落在哪个目录决定它怎么被播」。

## 去水印「去不干净」：根因是遮罩比水印小一圈 + 整帧并集

**症状**：`video/src/待机.mp4`（豆包生成，顶部/右下角有「豆包 AI生成」）处理后留淡淡字影。
单测第 120 帧：改动区相对背景最大偏差 195、均值 25.6，肉眼能看到字形的灰影。

**三个独立根因（都修了）**：

1. **遮罩只盖实心笔画，边缘那圈半透明像素没被标进来**。抗锯齿+压缩让字的边缘有 2~9px
   逐渐过渡的像素（实测帧 120/160 需要外扩 9px 才能全盖住），旧代码只填遮罩内的洞，
   边缘残留 → 一圈淡字影。这就是「去不干净」的主因。
2. **逐帧紧包围盒其实等于整帧**。遮罩底部有一条整行白线（y=719，全宽），
   它和顶部文字差了几百行，box 一并就是 1280×720 —— 旧 print 直接暴露
   `水印并集 1280x720 @(0,0)`。于是每帧按 1280×720 做 24 圈 `np.roll` 内填，
   **单视频 260.7s**（1000ms/帧）。
3. **内填是「从相邻像素一圈圈渗」**，取色点紧贴洞边，正好是那圈脏色，所以填出来的值本身偏亮。

**新实现**（全在 `make_pet_webm.py` 的 水印 段）：
- `_split_regions()`：按「连续有白像素的行段」切块（行间隔 >4 断开），每块单独裁框。
  一帧通常 1~3 块（顶部文字 + 右下角文字 + 底边线），最大块 1280x109。
- `_dilate(mask, grow)`：基础外扩（`--grow`，默认 4）。
- `_grow_into_fringe()`：再沿「明显偏离底色」的像素自适应长开，最多 14 圈，颜色回到底色就停。
  **底色必须用整帧主色 `_dominant_color()`**（隔 8 取样中位数）——
  一开始用裁剪框外圈的中位数，而框会框到角色，底色估歪 → 整条腿被当成水印一路吃掉
  （帧 5/197 惨案，改动 16000 px）。换整帧主色后生长自然停在绿色上。
- `_fill_4dir()`：洞内每个像素取上下左右最近非洞像素做距离加权（`1/(d+1)`），
  纯 numpy 的 `np.maximum/minimum.accumulate`，与洞的厚度无关；没有逐圈渗的中线接缝。

**代价/收益**：261s → 55s（5.5s 去水印 + VP9 编码为主），体感 4.7 倍。

**验证**：
- 全 241 帧扫过：纯背景区域残留 >25 偏差的像素从 86128(grow=4 旧填充) 降到 0~4。
- 关键三处前后对比图：顶部文字完全消失、右下角运动模糊的字基本消失（thresh 12 时 0 残留）、
  角色脚下裙摆/腿一根线没少。
- 成品 webm 解码后底部 3 行 alpha 全透明 → 那条整行白线确实被填掉了（否则会在脚下留一条白边）。
- 合成到白底看帧 5/88/120/197，无字影、角色完整。

**参数**：新增 `--grow`（基础外扩，默认 4）；`--passes` 保留成隐藏参数，传了就打印「已无意义」。
阈值 `thresh=12`（18 时右下角那帧还留 2px 残影，8 时会多吃 4000 px 角色周边，取中）。

**副产品结论**（值得记住的素材事实）：
- 豆包的水印**会移动**：多数帧在左上（y 41-78, x 56-226），过渡帧跑到右下（y 611-719），
  还有一条 y=719 的整行白线。所以遮罩必须逐帧用，不能合成一张静态区域。
- 遮罩与视频**帧对齐是正确的**（试过 ±1/±2/±4 偏移，0 最好），不需要补偿。

**遗留**：`dist/assets/webm/` 里那 106 个成品是旧算法（逐圈内填、整帧并集）产的，
如果想洗干净得拿原始 mp4 加 `--force` 重跑；`video/src` 现在只有 `待机.mp4` 一个源。

## 定档：assets/ 是项目文件、dist/ 是产物（17:36）

用户纠正了上一轮的方向：「根的 assets 属于项目文件，dist 中的属于打包后可分发的产物，

  大小和 mtime 都一致就跳过，否则 copy2；`dst` 里多出来的删掉（保证产物 = 工程内容）。
  `drop_old_layout()` 改成先用 `_covers()` 比对，老 `dist/DshPet/assets` 里的文件根里都有才整层删。
- **main.py**：`_assets_dir()` 候选序反转为 `HERE/assets` → `HERE/dist/assets`，

- **文档/注释**：README（目录树、数据流、第 3/4/5 节、打包一节全重写）、

  里的 `dist/assets` → `assets`、`make-webm.cmd`（纯 ASCII 注释）。

**踩到一个大坑**：`Path.rmdir()` 在这台机器的 F: 盘上是**递归删除**——
对非空目录不报错，直接把里面的文件删光。镜像后「清理空分类目录」那一步因此把刚同步好的
