## 鼠标碰撞（`physics.mouseCollision`，默认开）

需求：配置为 true 时鼠标参与碰撞——扫过宠物把它弹开；且**运行中可随时关**。

- `physics.cursor_push(body, cursor, v, entered=)`：纯函数。半径 10 的小球。
  **第一版判据写错了**（速度 <200px/s 不触发）→ 只有猛撞才弹，渔夫反馈「慢慢移过去不弹」。
  改成**进入沿**触发：`entered` 由 `window._mouse_inside` 上一帧状态给出，慢速碰上照样弹；
  力度 clamp(speed×1.25, 260, 2800)；`speed < 25px/s` 视为手没动不弹（防宠物自己撞静止的手）。
  方向 = 0.7 扫向 + 0.3 离心 + 0.45 上抬。
- `window.py`：每只一个 16ms `QTimer` 轮询 `QCursor.pos()`（Qt 收不到窗口外的鼠标事件），
  `_poke_mouse()` 里排除 drag/throw、按着键、不可见，300ms 冷却。
- `_start_throw(vx, vy, *, shot=True)`：鼠标弹飞 `shot=False` → 不调 `on_shot_start`、落地不调
  `_end_shot`，投篮游戏不会把它当成一投（`_throw_shot` 记这一段）。
- 菜单「鼠标碰到就弹开」勾选项 → `PetApp.set_mouse_collision()` 全局生效，只改内存不写文件；
  `reload_config` 按文件值复位。`config.jsonc` 里 `"mouseCollision": true`。

**验证**（`.workbuddy/_out_test/mouse_poke.py`，离屏 + 伪造 `QCursor.pos`）：
慢慢挪进去 150px/s → 弹（v≈247）／猛撞 → 弹得更远（v≈2266）／静止搭着 idle／
已在身上继续挪不重复弹／按着键不触发／落定后 `抛掷钩子=[]`（不冒充一投）／关掉即失效／
菜单重开生效／重载配置按文件关掉／菜单四条顺序正确。
真机双屏核对光标逻辑坐标与窗口几何同一空间（主屏 1.5、副屏 1.25 偏差 0）。
回归 `celebrate_paths.py` 三条庆祝路径仍 OK。

## 定稿：速度门槛（同日第二次反馈后）

渔夫看完进入沿版本又说「**慢慢移过去还是会弹**」——他要的就是「慢不弹、快才弹」。
最终形态：`cursor_push(body, cursor, v, min_speed=)`，**删掉 `entered` 参数和 `_mouse_inside` 状态**，
只按速度判；门槛 `physics.mouseMinSpeed`（config 可调，默认 800，夹在 50~5000）。

实测：0/120/300/600 px/s → idle；900 → 弹（v≈1146,-246）；2000 → v≈2444；4000 → v≈2738（撞上限附近）。
边界：没碰到／冷却期／按着键／被拎／游戏开着 → 都不弹；关掉 timer 停；门槛调 3000 时 2000 不弹、3200 弹；
戳飞那一段 `抛掷钩子=[]`。

**教训**：这个需求问了两轮才对齐，说明「碰到就弹」和「撞到才弹」在他脑子里是两个词——
以后碰到类似「灵敏度」类反馈，先问一句「你要的是贴上去就弹，还是得撞一下」，别自己猜。

**坑**：`body_box` 的左边缘是 `x + 200/640*width`，`pets[0].size` 是 320 就不是 144 而是 100 ——
探针里按固定像素写"框外/框内"坐标会假失败，得按 `width` 现算。
