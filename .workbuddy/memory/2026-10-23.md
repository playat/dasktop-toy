## 桌面端轻量化调研（只出方案，未实施）

产出：`docs/桌面端轻量化方案.md`

**实测数据（关键依据）：**
- `~/.dsh/electron` 实际 348MB（electron.exe 215M + locales 47M + dxcompiler 25M）
- `node.exe` (v22) 84MB —— 这是「用 Node 重写」的死穴
- 素材 106 个 webm / 52MB / 平均 500KB
- 本机：rustc 1.94.1（msvc）已装，WebView2 156 已装，MSVC link.exe 未确认

**核心发现：渲染层零 Electron 依赖。** `sprite.js`(1755) + `pet.ts`(2338) 只用了 DOM/`<video>`/CSS；
Electron 桥接面只有 `preload.js` 一个 `window.petBridge` + `main.js` 7 个 IPC handler。
所以「换壳」的真实工作量只有约 800 行（Tauri Rust 700 + JS 适配 100）。

**结论排序：**
1. Tauri 换壳（~5MB，前端 100% 复用，3~5 天）← 推荐
2. Node + C++ 壳（86MB，等于多背一个 node.exe，无理由）
3. Python + PySide6 自绘（~75MB，重写 7500 行，透明视频要 pyav 自解帧，只能 Windows，2~4 周）

**否决项：** Electron 瘦身（215M 主二进制砍不掉）、Edge `--app` 模式（无法透明）、
tkinter 色键（边缘锯齿）、Qt WebEngine（比 Electron 还重）。

**必须先做的 spike：** Tauri 透明无边框窗口内放 `<video autoplay muted loop>` 播 VP9-alpha，
确认真透明 + 移动不拖影。失败就止损回 Electron。
风险：Tauri 的 `set_ignore_cursor_events` 没有 Electron `forward:true` 的语义，
需 Rust 侧 30Hz `GetCursorPos` 轮询补；`dpi-linearization.js` 的补丁不能直接搬。

## pet_py 自包含化 + 修「宠物不显示」

**1. 脚本收进 pet_py**
- `.venv` 从项目根移到 `pet_py/.venv`（venv 复制/移动后仍可用，Windows 下 prefix 按 exe 位置算）
- `pet_py/run-pet.cmd`、`pet_py/setup-pet.cmd` 新增；根目录那两个已删

- 现在 `pet_py/` 整个目录搬走即可独立运行

**2. 真凶：窗口被推到屏幕外（不是没启动）**
- 现象：进程正常、日志正常、`IsWindowVisible=1`，但人眼什么都看不到
- 原因：`main.py` 混用坐标系统 —— `GetSystemMetrics(0)` 给物理像素 3840，
  却喂给 Qt 的 `move()`（逻辑像素）。150% 缩放下窗口实际落在物理 4728，屏幕只有 3840
- 修法：`place_window()` 全部改用 `app.primaryScreen().availableGeometry()` + 逻辑坐标，
  并加「中心点必须在某个屏幕内」的兜底，落不进去就居中
- 修后：`QRect(1872, 96, 640, 360) · 屏幕 2560x1392 @ 1.5x` → 右边缘 2512 < 2560 ✅
- 验证手段：PrintWindow(PW_RENDERFULLCONTENT=2) 抓分层窗口内容 → 30763 种颜色、绿幕残留 0%
  （ImageGrab 抓不到 layered 窗口，别再试）

## 落定：落地 Q 弹重做 + 松手行为（M4 后修）

- **真正的 bug 是缩放锚点错了**：`paintEvent` 里 `transform.scale(sx, sy)` 之前只 translate 了 Y，
  横向是**以 x=0（窗口左边缘）为原点**放大的 → 角色往左钉住、右侧超出窗口被裁掉，
  看起来就是"变形严重 + 宽度乱变"。现在改成以「水平中心 + 脚底」为锚点（先 translate(cx, feet)）。
- 参数收敛（`pet_py/physics.py`）：下压 0.55→0.72（45%→28% 压深）、轻落下限 0.8→0.9、
  时长 220→190ms、回弹过冲 1.12→1.06、横向耦合 0.35→0.12（最深只宽 3.4%，原 15.7%）。
  新增常量 `SQ_LIGHT_SQUASH` / `SQ_MAX_STRETCH` / `SQ_WIDTH_GAIN`。
- **松手语义改了**（`window.py:mouseReleaseEvent`）：`estimate_release_velocity` 返回 None（低于
  DEAD_ZONE_SPEED=500px/s 的死区）时**不再调用 `_start_throw(0,0)` 自由落体**，
  改为原地站住 + `_play_idle(force=True)`。只有真甩出去才走抛掷/反弹/落地挤压。

- **点击穿透**：Windows 分层窗口按 per-pixel alpha 命中，alpha=0 区域鼠标事件直接穿到下层。

- 多开/托盘/右键菜单/Ctrl+C/状态机/抛掷/落地挤压/点播/回位/重载：冒烟跑通，`[pet] 窗口 462x260 QRect(2074,1141)`。

1. **多屏边界**（`window.py:_sync_area`）：`_bounds` 原来只按主屏算，拖到副屏（x=-1920..-384）甩出去
   会被主屏 max_x/min_x 钳回来 → 瞬移回主屏边缘。现在甩出/走位前 `screenAt(中心)` 同步可视区。
   实测副屏 bounds = min_x -2120 / max_x -824，正确。**副作用：等于 confineToScreen=true**（甩出锁在所站那块屏）。
2. **pets[].fixedEnabled 形同虚设**：只读了 `pets[0].fixed` 当全局，窗口里用 `cfg.fixed`。

## 修复：venv 被移动后彻底损坏 → 重建

**症状**：用户终端里 `source .venv/Scripts/activate` 后进不去，命令全废。

**根因**：`pet_py/.venv` 是从工作区根 `.venv` **移动**过来的（pyvenv.cfg 里 `command` 仍写着
`-m venv F:/OTHER/dsh-pet/.venv`）。移动 venv 会留下两类硬编码绝对路径：
1. `Scripts/activate`（第 44/49 行）、`activate.bat`（第 11 行）里的 `VIRTUAL_ENV` → 指向旧的
   `F:/OTHER/dsh-pet/.venv`，激活后 PATH 加了个不存在的目录，`python` 直接找不到。
2. `Scripts/*.exe` 的 launcher（pip.exe 等）内嵌旧解释器路径 → `pip.exe` 静默 rc=1 无输出。
   `python.exe` 本身没事（靠 pyvenv.cfg 的 `home` 定位），`python -m pip` 也正常。

**处理**：用户拍板重建（不是改字符串）。
`rm -rf .venv && python -m venv .venv && .venv\Scripts\python.exe -m pip install -i 腾讯云源 -r requirements.txt`
→ PySide6 6.12.0 / av 19.0.2 / numpy 2.5.4 / pillow 13.0.0，激活后 prefix 与 pip 均正确，冒烟启动正常。
基解释器用 PATH 里的 `python`（3.13.12），**没用 `py -3`**（那是 3.14.4，PySide6 轮子不一定有）。
`setup-pet.cmd` 已同步改成优先 `python`、fallback `py -3`，自检加了 pillow。

**教训：venv 永远别用 mv 搬，搬完必须删了重建。**

## 新增打包脚本 build.py / build.cmd（PyInstaller）

`build.py`（带参数） + `build.cmd`（双击）。默认 **onedir**：`dist/DshPet/DshPet.exe`，136MB
（_internal 78MB + assets 53MB）。实测：`os.startfile` 拉起后进程存活，`dsh-pet.log` 记录
`窗口 462x260 QRect(2074,1141)`、`[anim] idle → 待机呼吸休闲` —— Qt/PyAV/素材路径全部正常。

**关键设计**：
- **素材和配置外置在 exe 同级，不打进包**。`main.py` 新增 `_app_dir()`：frozen →
  `Path(sys.executable).parent`，否则脚本目录。`HERE` / `CONFIG_FILE` / `ASSETS` 全跟着它走，
  所以换素材、改配置都不用重编译。
- **`--windowed` 下 `sys.stdout is None`**，而 main.py 到处是 `print(..., flush=True)` → 会 AttributeError。
  顶部兜住：为 None 时 open `dsh-pet.log`（失败退 devnull），实测日志正常落盘。
- 必须 `--collect-all av`，否则 PyAV 的 libvpx dll 不进包。
- 图标：`_first_frame_rgba()` 复用 libvpx-vp9 解码 → `alpha[alpha<16]=0` → bbox 裁 → 256 画布居中 → 多尺寸 ico。

**坑（重要）**：PyInstaller 的 `--clean` 会去清 `%LOCALAPPDATA%\pyinstaller` 缓存（本次 78 个文件），
在受限沙箱里触发 `SAFE_DELETE_BULK_CONFIRM_REQUIRED` 被拦，构建直接失败且只留一句
"[失败] PyInstaller 出错"。已从命令行移除，只用 build.py 自己的 `--clean` 删项目内 build/dist。
