# 2026-11-11

## "一直连续待机" 第二弹：游戏锁把宠物按成雕像

**现象**：连续待机不换动作，用户怀疑一直处于投篮游戏里。

**实测**（`.workbuddy/_out_test/game_idle.py`）：开局后 20 秒只播 `idle` + `hold`，
一个 action 都没有，`game_lock=True`。

**根因**：`_roll_next()` 里
```python
if self.game_lock:
    self._hold_idle()
    return
```
游戏锁的本意只是「别走位/转身，免得玩家追着抓」，但写成了整局只播待机、且**不排下一次掷骰**。
所以只要筐还在（哪怕被拖到别的屏/被藏起来），宠物就一直站着循环待机 —— 跟上一轮的
`_play_idle` 断链是两回事，两个都会表现成"永远待机"。

**修**：

- `_roll_next`：`stay = self._fixed or self.game_lock` → turn/move 权重归零，**原地小动作照常**（action 池）。
- `set_game_lock`：上锁时若在走位则停住+切待机；不管上锁解锁，只要 gap 没排就 `_schedule_next("idle")`
  （旧码上锁时 `_gap_timer.stop()` 后不排，等于必停）。
- `_guard_idle` 去掉 `game_lock` 判断（游戏期间也允许自愈）。
- 新增 `BasketWindow._clamp_to_screens()`：松手时筐整体在屏幕外就推回最近屏、留 48px。
  只在 release 调用，拖动中不碰（否则和鼠标位置打架、丢抓取）。

**验证**：game_idle 再跑 → `action 2 / idle 1 / hold 1`，游戏开着也会撸猫、吃东西；
clamp 离屏测试三种位置（屏内不动 / 左上出界 / 右下出界）全部回拉成功。

> 排查口诀：**"永远待机"先分两种** —— 筐还在 = `game_lock`；筐不在也这样 = 调度链断了
> （看有没有 `[anim] 调度链断过 → 补排下一次掷骰` 这行日志）。
