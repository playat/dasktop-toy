## 会话状态观察：pet_state.py 集成（14:35→）

用户给了 `pet_state.py`（读 dsh 会话日志折叠状态），要求集成并「让桌宠按状态反应」，
并指出难点是**什么时候触发**。

**先修了个致命 bug**：`pet_state._decompress()` 只调模块级 `zstd.decompress()`，
而 dsh 写的是**流式帧**（帧头没有 content size），python-zstandard 直接抛
`could not determine content size in frame header` → `_decode_frames` 吞掉异常 →
**0 个事件**（表现是「日志是空的」，其实 15KB 日志里有 11 帧）。
修法：三级降级 —— 模块级 → `ZstdDecompressor().decompress(blob, max_output_size=64<<20)`
→ `decompressobj()`。修完 `pet_state.py --all` 立刻能出 `session_id / project / turn`。
（顺带：`first_read_limit=4MB` 会跳过文件头，大日志的 `session_id/cwd` 很可能为空 →
`session._sid_of()` 用 `path` 兜底。）

**新增 `session.py`**（适配层，和 `balance.py` 同一套路）：
- `SessionWatcher(QObject)`：工作线程按 `pollMs` 轮询，`build_payload()` 压成普通 dict，
  经 `Signal(object)` 回主线程（不能在子线程碰 Qt）。
- `ReactionPolicy`：纯逻辑，`plan(snapshot)` → 动作元组 `("hold", 素材|None)` /
  `("play", 素材)` / `("say", 文本)`。**触发时机的六条规则写在文件头**：
  ① 只认跃迁不认状态 ② 忙碌内部（thinking↔tool）抖动合并 `minHoldMs`，从 idle 进忙碌立即
  ③ 首次/换会话只对齐不复读（不弹气泡） ④ 一次性事件走 notices ⑤ 久等/久忙才催且有上限
  ⑥ 主会话按「等主人>忙碌>空闲+最近活动」挑，同档粘住当前。
  催促计时用「我们确认状态的时刻」而非 turn 起点，忙碌内部一切换就清零（在动=没卡住）。

**窗口层**：`PetWindow.set_status()` / `_apply_status()` / `play_effect()`，
`_after_oneshot()` 里状态动画**播完自动重播**（工作状态是持续的，不能播一遍回去发呆），
拖拽/飞行/被占用时挂起，`_roll_next()` 里补上。

**事件层**：`on_session_snapshot()` 执行动作；`on_work_status()` 在 `session_ready` 时直接 return
（日志观察优先，DSH 的 workStatus 让位，避免两个来源抢同一个动画）。菜单多一行「会话：…」。

**依赖**：`zstandard`（venv 已装；`requirements.txt` 已加；`build.py` 加了
`--collect-all zstandard`，收不全的话打包版会静默降级）。

**验证**：策略单测（跃迁/抖动/子形态/静默/粘会话/催的上限都覆盖）；临时 DSH_HOME + 假
`session.*.jsonl` 时间线联调 → turn/start 出思考冒泡+「开工啦」、tool/call 换忙碌点按且不
说话、approval 出原地踱步+日志原文、turn/end 出雀跃+「干完了」、hold 清空回待机；
真实日志下 `brief='闲 · 余额不够了，任务中断 · @default-workspace'`、启动不弹气泡、
`on_work_status` 确实让位。

## 实测：日志 → 桌宠的延迟（15:35）

用户问「文件里的状态，桌宠怎么马上读到」。不是 file watcher，是 `session.poll_ms`（默认 1500ms）
轮询 + `LogTail.offset` 增量读。实测（临时 DSH_HOME + 真追加一行）：
写入 `turn/start` → 读到 thinking **1023 ms**；写入 `tool/call` → 工具变 Bash **1509 ms**
（均匀落在 0~1500ms，平均 750ms）。
单次 poll 成本：首次读全量 37ms（4 个会话），之后无新内容 **0.05ms**（只有 getsize 比 offset）。
→ 想更快就把 `session.pollMs` 调到 800，下限被夹到 300。
