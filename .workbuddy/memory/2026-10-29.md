# 2026-10-29

## 调研：抠像判据能不能翻译成 ffmpeg 命令行

机主问「mask 脚本里的参数在 ffmpeg 里怎么写」。用 PyAV 内置的 libavfilter（471 个滤镜，含
chromakey/colorkey/geq/removelogo/despill）在真实帧上实测，**不用装 ffmpeg CLI**。

### 结论：colorkey / chromakey 在这套素材上不可用

素材绿幕是**低饱和灰绿**（中位 RGB (100,142,109)，sat≈0.30），角色是白色 (155,150,147)，
两者在 RGB 欧氏距离空间只差 68（colorkey 的 similarity 标尺 ≈ sqrt(3)*255=441，即 0.154）。

| 滤镜 | 参数 | 角色保留 | 背景残留 |
|---|---|---|---|
| colorkey 0x648e6d | sim=0.10 | 94.9% | 20.14% |
| colorkey | sim=0.13 | 88.2% | 7.27% |
| colorkey | sim=0.16 | **81.6%** | 0.39% |
| chromakey 0x648e6d | sim=0.10 | **0.8%** | 0% |

chromakey 更惨：绿幕 chroma 只有 (119,110)，距中性 (128,128) 才 20，阈值一到中性就把白角色
全抠光。这正是脚本注释里「刻意不用 chromakey 的 YUV 距离」的实测依据（原来只是断言）。
根因：**绿幕不是一个色点，是一条宽带**（有色晕/渐变），距离判据抓不住，范围判据（色相区间）才抓得住。

### geq 可以 100% 复刻

`format=rgba, geq=r='r(X,Y)':g='g(X,Y)':b='b(X,Y)':a='<表达式>'`，表达式用嵌套 if 表达
「明度下限 / 绿占优 / 饱和度下限 / 色相区间」四条：

| 版本 | 长度 | 单帧 | 角色保留 | 一致率 |
|---|---|---|---|---|
| 完整（含色相 70~170） | 393 字符 | 359ms | 100% | 100.00% |
| **去掉色相区间（推荐）** | 197 字符 | 210ms | 100% | 99.98% |
| 只留绿占优+明度 | 87 字符 | 128ms | 97.4% | 99.66% |

numpy 原判据 117ms/帧。**色相区间可以省**：G 最大时 hue∈60~180，绿幕在 120 附近，两端裁掉不影响。

色相条件推导（G 为最大通道时，省掉六段分支）：
`hue = 60*(2+(B-R)/(max-min))` → `hue≥70 ⟺ R-B ≤ 0.8333*(max-min)`；`hue≤170 ⟺ B-R ≤ 0.8333*(max-min)`

### ffmpeg 做不到的三件事

1. **逐帧水印 mask 的填充**（fill_nn 周围像素插值）—— `delogo` 只有矩形，`removelogo` 只吃静态 bmp。
   直接用 mask 做 alphamerge 会把水印区挖成洞（不是填充），且 mask 底部有一整行白线（y=719）会打穿一条。
2. **`_strip_watermark` 自动识别左上角白字** —— 无等价滤镜。
3. **归一化的站立高度测量**（首尾 5 帧量站立高/中心/脚底再定缩放比）—— ffmpeg 里必须先手工量好填死。

### 水印 mask 实测形态

`video/watermark_mask_v5.mkv` 1280×720 gray，**逐帧变化**：f0 白 0.14%、f120 白 0.57%（y 41~719）、
f200 白 1.12%。每帧都有 1 行近满行白（y=719 整行），所以「整帧并集」会覆盖全画面 —— 原脚本逐帧取交集是对的。

## 修：右键「关掉这只」把全部宠物关掉了

`_show_menu` 里 `on_quit=self.quit` 是硬编码的全局退出，多开之后在任意一只上点「退出」都走同一条路。

改法（三文件）：
- `main.py`：新增 `close_pet(win)` —— 从 `windows` 移除 → `events.detach(win)` → `shutdown/close/deleteLater`
  → 空了才 `quit()`（顺带 `tray.hide()`）。菜单按 `len(windows) <= 1` 选 `self.quit` 还是 `close_pet(win)`，
  文案 `quit_text="退出" / "关掉这只"`。
- `menu.py`：`build_menu` 加 `quit_text: str = "退出"`。
- `events.py`：`attach()` 返回唯一 key（`pet_id`、`pet_id#2`…），新增 `detach(win)` 按窗口反查清理
  `_bubbles/_windows/_locked/_history/_ai_busy`；`_pet_arg` 去掉 `#N` 后缀再传给 DSH。

**顺带修掉的老问题**：原来多开时所有宠物共用 `pet_id` 当 `_windows` 的键，后一只把前一只顶掉，
事件只落到最后一只；现在每只独立 key，`pet_key` 存窗口上，`_show_menu` 用它注入菜单项。
`_refresh_tray_tip` 原来按 `cfg.pets` 数列名字（多开就对不上），改成按真实 `windows` 数 + `pet_name()`。

## 方案：投篮游戏（只出方案，还没写代码）

机主要「右键菜单开一局投篮」：可拖的篮筐窗口（先蓝框占位，之后换图）+ 宠物头顶常驻计分 +
拖宠物甩出（复用现有抛掷物理）→ 进筐计分 1~10 + 头顶飘 `+10`，右键篮筐或宠物菜单结束。

定下的关键设计（**下次实现直接照这个走**）：
- 三个新东西：`basket.py` 里的 `BasketWindow`（筐）/ `ScoreBadge`（头顶计分+飘字）/ `BasketGame`（控制器）。
- **判定点 = 宠物身体中心**（`physics.body_box` 已经有），判定圆半径 = 筐口内径 × ratio。
  **必须做扫掠**：拿上一帧中心→当前帧中心的线段跟圆求最近距离，否则高速一帧跨过整个筐会漏判。
- 分档 u = d/R：u≤0.2 → 10 分；否则 `round(10-9*(u-0.2)/0.8)`（0.4→8、0.6→6、0.8→3、1.0→1）；u>1 没进。
- 一投只计一次：从 `mouseReleaseEvent` 甩出（`on_shot_start`）到 `_drive_throw` 的 at_rest（`on_shot_land`）
  为一个 shot，`shot_scored` 上锁。
- 接入点：`_drive_throw` 每步回调 `on_throw_step(p0,p1)`（**在 move() 之后取坐标**）、`menu.build_menu` 加
  `game_action` 槽位、`main.PetApp` 持 game 并在 `close_pet/reload/quit` 里 `stop()`。
- 游戏期间要 `game_lock`：`_roll_next` 只播待机，否则宠物自己走位/转身，玩家抓不到。
- 筐窗口**不能**用 `WindowTransparentForInput`（要拖），用 `setMask(alpha)` 让透明区穿透，
  这样宠物停在筐后面还能点得到。徽章反过来用 `WindowTransparentForInput`，且**不复用 SpeechBubble**
  （会被 session/碎碎念覆盖）。
- 配置段 `basketball`：image / width / height / mouthRatio / hitRatio / perfectRatio / celebrateAnim。

验证（离屏，替换 `main.build_menu` 截获菜单，**不要 exec**）：2 只 → keys `['main','main#2']`、两只气泡不同、
多只文案「关掉这只」、关第二只后 keys 只剩 `['main']`、气泡已关、events 里无残留；再关 → 文案「退出」、
窗口 0、`quit()` 走完。3 只关中间那只 → `['main','main#3']`，`say()` 分发正常不崩，
被关窗口的 C++ 对象确已回收（测试里访问 `mid.isVisible()` 会抛 `RuntimeError`，属于预期）。

## 追加：投篮命中后回位（15:20）

需求「投入篮筐后，宠物回到开始投掷的位置」。

- **起点**：`_on_shot_start()` 里存 `(win.x(), win.y())` —— `_start_throw` 先记 ThrowState 再回调，
  读到的是**松手原地**，宠物还没飞。存在 `BasketGame._home`，每次新投覆盖。
- **什么时候回**：在 `_settle()`（命中计分那一刻）就 `_home_timer.start(returnDelayMs)`，
  **不等落地**。实测撞墙弹跳能耗好几秒，等 at_rest 再回去太拖。
- **回位同时收掉飞行**：`window.abort_throw()`（新增）= `_throw=None; state="idle"; _play_idle()`。
  **不要调 `_end_shot()`** —— 它会再报一次「一投结束」，庆祝播两遍。
- **不抢鼠标**：`_go_home` 里 `state == "drag"` 直接放弃（`_home` 已清空，不会重试）。
- **庆祝防重**：回位时 `_celebrate=False` 再播庆祝；`_on_shot_land` 里加
  `if self._home_timer.isActive(): return`，落地早于回位就交给回位那一次播。
- 配置：`basketball.returnHome`（默认 true）、`returnDelayMs`（默认 220）。
- 坑：`mouth_center` 是筐窗口几何，反解初速时 `physics.throw_step` **有水平阻尼**，
  vx 越小累积偏差越大（vx=900 → 3px，vx=700 → 37px），打表断言别把分档写死成 10。

验证（离屏）：真实抛物线命中 → 220ms 后回到 `(100,300)`、`state` 变 action（庆祝）、`_home` 已清；
命中后立刻 `state="drag"` → 停在手里不被拽回；未命中 → 原地不动；`returnHome=false` → 不回位；`stop()` 清计时器。
测试产生的 `basket-score.json` 已删。

## 追加：开局筐放「宠物另一边」（15:30）

`BasketGame._initial_pos()` 原本是硬编码「右边优先」，宠物靠屏幕中间偏右时筐也出右边，两边挤一起。
现在按**屏幕中线**判断：`pet_cx <= area.center().x()` → 优先右边，否则优先左边；那侧塞不下
（`lo..hi` 越界）就退另一侧；两边都不行（窄屏 + 462 宽宠物）按溢出量挑一侧再夹回屏内。
右键「回到宠物旁边」= `_reset_pos()` 走同一函数，所以会跟着宠物当前所在的半边换边。

离屏验证（800×800、宠物 462 宽、筐 260）：宠物 x=0 → 筐 502；x=338 → 筐 38；x=440 → 筐 140；
竖直仍在屏内；`start()` 与 `_reset_pos()` 一致。
